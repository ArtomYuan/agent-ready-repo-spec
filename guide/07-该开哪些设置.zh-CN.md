# 07 · 该开哪些设置

[English](07-该开哪些设置.md) · **简体中文**

> 这一章是**开关清单**，不是决策。决策（选哪一档、谁可以绕过）在 [guide/00](00-接入决策.zh-CN.md)；
> 这一章是"去哪点"。
>
> 依据：GitHub 自己的 rulesets 与仓库设置文档，以及本仓库一次真实事故——**必需检查写错名字，把 main 锁死**
> （[ADR-0010](../docs/adr/0010-required-checks-self-lock.md)）。

---

## 0. 一条原则

**设置是"不依赖记忆的约束"。** 只要某件事必须永远成立，就用平台机制表达，而不是写进文档里的一个句子。

推论同样重要：**每个你打开的开关都必须有主人。** 没人负责的设置页，在它把仓库锁死的那天也没人会去修。

---

## 1. 合并相关 —— 全部打开

| 设置 | 值 | 不开会怎样 | 在哪 |
|---|---|---|---|
| Require a pull request | 开 | 直推绕过你建的所有门禁 | Settings → General → Pull Requests |
| 合并方式 | **只允许 squash** | 历史里 merge commit 与 squash 混着来，revert 变猜谜 | 同一页 |
| **Automatically delete head branches** | 开 | 合并后的分支一直留着（本仓库积到过 13 个） | 同一页 |
| Allow auto-merge | 开（可选） | 批准之后还要人手点一次 | 同一页 |

> **关于自动删除**：它只在**合并**时触发。PR 被**关闭**的分支会一直留着，要手工删。

---

## 2. Ruleset / 分支保护 —— 全部打开

| 规则 | 值 | 不开会怎样 |
|---|---|---|
| `deletion` | 开 | 主分支可能被误删 |
| `non_fast_forward` | 开 | force push 会毁掉历史，任何回滚计划随之失效 |
| `required_status_checks` | 填**真实存在**的检查名 | 见 §6——名字写错就永久锁死 main |
| `pull_request` → 批准数 | **≥ 1** | agent 可以不经评审合并自己的活 |
| `pull_request` → 驳回过期批准 | 开 | 最后一次提交之前的批准，等于什么都没核 |
| `pull_request` → **要求"最后一次推送"之后有人批准** | 开 | 最后推送的人可以自己批自己 |
| `pull_request` → 要求 Code Owners 复核 | **有 `CODEOWNERS` 才开** | 不开的话那个文件就是装饰 |
| `pull_request` → 必须解决所有讨论 | 开 | "这里还得改"的评论会被连带合进去 |
| `required_linear_history` | 开 | 历史不可读，cherry-pick 与审计都变难 |

**允许的合并方式**：只留 squash。混着用，仓库最后会出现三种历史形态。

---

## 3. 谁能绕过 —— 必须显式回答

| 问题 | 建议答案 |
|---|---|
| 管理员可以绕过吗 | **不可以。** 需要应急通道就显式写进 ruleset 的 bypass 名单，而不是打开"管理员可绕过" |
| 谁能改 ruleset | 把具体的人或团队写进采用记录 |
| 锁死了怎么办 | 一段破窗流程，同样写进采用记录 |

为什么这是 `must`：**写代码的人和能改门禁的人，通常不是同一个人。**
能 push 的 token 一般改不了 ruleset——本仓库就是这么被锁住的
（[ADR-0010](../docs/adr/0010-required-checks-self-lock.md)）。

---

## 4. Actions —— 把默认值收紧

| 设置 | 值 | 不开会怎样 |
|---|---|---|
| Workflow permissions（默认 `GITHUB_TOKEN`） | **只读** | 每个 workflow 默认都有仓库写权限 |
| 允许 Actions 创建/批准 PR | 关 | workflow 可以批准自己的 PR |
| Fork PR 的 workflow | **首次贡献者需批准** | 陌生人的 fork 能在你的 runner 上跑代码 |
| 允许的 actions | "只允许选定 actions"（至少：禁止未固定版本的第三方 action） | 供应链风险，且没有评审路径 |
| 日志 / 产物保留期 | 调短（如 30 天） | 存储无限增长，没人注意 |

---

## 5. 安全 —— 默认开，维护成本极低

| 设置 | 值 | 不开会怎样 |
|---|---|---|
| 私密漏洞上报 | 开 | 研究者没有私密通道，报告落到公开 issue |
| Dependabot alerts | 开 | 你是从陌生人嘴里知道依赖有洞的 |
| Dependabot security updates | 开 | 只有告警没有升级，等于噪音 |
| Secret scanning（+ push protection） | 开（平台支持时） | token 泄露要等被用掉才发现 |
| Code scanning | 视情况 | 出代码时值，只出 markdown 时是噪音 |

---

## 6. 唯一会把你自己锁在外面的一项

`required_status_checks` 存的是**名字**，每个名字都必须有东西去上报。删掉 workflow 或改 job 名，
那个名字就永久停在 `Expected — Waiting for status to be reported`——**不超时，也不认历史提交**。

三条规矩：

1. 检查名一律**从下拉里选**，不要手打（非 ASCII 名字里错一个字，界面上完全看不出来，效果上是致命的）。
2. 改 job 名走三步：加新名 job → 改 ruleset → 下一个 PR 删旧 job。
3. 把当前必需检查名写进 `AGENTS.md`，让下一个人知道 workflow 撑着什么。

完整事故：[guide/05 附录](05-Agent参与怎么管理.zh-CN.md) · [ADR-0010](../docs/adr/0010-required-checks-self-lock.md)。

## 7. 记录设置，而不只是点了开关

在采用记录里加一节 `## 设置`（模板见 [templates/adoption.md.tmpl](../templates/adoption.md.tmpl)）：

```markdown
## 设置（2026-11-18）

| 设置 | 值 | 谁能改 |
|---|---|---|
| 合并方式 | 只允许 squash | @owner |
| 必需检查 | 链接检查、双语配对 | @owner |
| 管理员绕过 | 不允许；破窗见 ADR-0010 | @owner |
| Actions 默认权限 | 只读 | @owner |
```

少了"谁能改"这一列，这张表记录的是愿望，不是状态。

---

## 8. 本仓库实际开了什么

| 设置 | 状态 |
|---|---|
| Require a pull request | 开 |
| 只允许 squash | 开 |
| 自动删除 head 分支 | 开（2026-11-17 才打开，此前积了 13 个陈旧分支） |
| ruleset `main` | `deletion` · `non_fast_forward` · `required_status_checks`（链接检查 / 双语配对）· `pull_request`（1 批准、驳回过期、要求最后推送后批准、必须解决讨论）· `required_linear_history` |
| 管理员绕过 | 无（`bypass_actors: []`）；**能否改 ruleset 取决于 `administration` 权限，与 bypass 名单无关**——干活用的 App token 通常没有该权限 |
| Actions 默认权限 | **尚未核实**——这是真实缺口，写在这里而不是藏起来 |
