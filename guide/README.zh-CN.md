# 指导正文

[English](README.md) · **简体中文**

这个目录是**指导**，不是判据。用不用、用多少，由采用它的仓库决定；
但**决定要一次做、要落在被管理的那个库里**——见 [00-接入决策](00-接入决策.zh-CN.md)。

它回答六件事：

1. 接入时**选哪一档**，以及决定记在哪
2. 一个 GitHub 仓库**应该有什么文档**
3. 应该有什么**结构**
4. 这些文档**应该怎么写**
5. **Agent 应该怎么用**，以及 **agent 参与开发时该怎么管理**
6. 换会话 / 换 agent 时，**状态与待办放哪**；以及**发布**怎么界定

`rules/` `checker/` `templates/` 只是配套的自查工具与样例——**它们不替你做决定，也不替你执行**。

## 怎么读

- **第一次接入** → 先读 **00**，把选项定下来并记进自己的仓库，再往下看。
- 只想写对某一份文件 → 读 **03** 里对应的那一节，照骨架写，再用"反例"对照一遍。
- 要新建仓库 → 按 01 → 02 → 03 的顺序读一遍。
- 要把仓库交给 agent → 读 **04**；agent 提交变多 → 读 **05**。
- **立项：范围、顺序、进度分别放哪** → 读 **06** 第 1 节；**发布** → 第 2 节。
- **换会话 / 换 agent 接手** → 读 **06** 第 3 节。
- 想自查"我有没有遗漏" → 用 `checker/spec-check.ps1`（见仓库根 README）。
  它只报事实，**不评价你选的档位对不对**。

## 一条贯穿全篇的判据

> **文档的每一行，都要能回答"读者读完这一行，下一步做什么"。**

回答不了的句子，删掉。
