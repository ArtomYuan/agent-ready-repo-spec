# 06 · 状态与待办

> 这一章只解决一个场景：**你要离开，换一个 agent 或开一个新会话接手。**
> 它回答三件事：状态放哪、待办放哪、怎么保证它不会过期。

---

## 0. 先承认一个事实：这个问题没有"纯文档解法"

工具侧的机制只覆盖一部分：

| 机制 | 覆盖范围 | 覆盖不了 |
|---|---|---|
| 会话恢复（`--continue` / `--resume`） | 同一台机器上的同一个会话 | 换机器、换人、开新会话 |
| 自动记忆（`MEMORY.md` + 主题文件） | 同一台机器上跨会话 | 不进 git，换机器即失忆 |
| 子代理记忆（`memory: project`） | 可提交，跨机器 | 只服务那个子代理 |

而"写进仓库"这条路，实测也不自动成立。本仓库自己就是个反例：

- 4 个 PR 的描述各 **163 字**，全是模板套话（"改了什么：<标题>" + "验证：全绿"）；
- 打开中的 issue **0 个**；
- 提交信息**只有标题 + `(#N)`**。

结果：新会话能回答"**做了什么**"（标题 + diff），回答不了"**下一步做什么**"。

**结论：状态必须落在一个"必然会存在"的载体上；靠记性维护的文档一定会忘。**

---

## 1. 三种承载方式，按可靠性排

| 方式 | 可靠性 | 什么时候用 | 代价 |
|---|---|---|---|
| **A 靠记性写文档** | 低 | 不建议 | 会忘、会过期，而且会变成第二真相源 |
| **B 模板必填 + 评审** | 中 | 有人评审的仓库 | 漏写会被 review 挡住；没人看时失效 |
| **C 写进工具** | 高 | **已经有自动化发布路径**（脚本或 CI 发布） | 工具多一两个必填参数；离线/无令牌时用不了 |

方式 C 的意思是：把「下一步 / 非目标 / 怎么验证的」做成**发布流程的必填项**。
漏写的后果是**发不出去**，而不是文档静默过期——**这是唯一不依赖记性的强制点。**

---

## 2. 推荐规则：按你的实际情况往下落

1. **已有自动化发布** → 选 **C**。发布参数里加"下一步（没有就显式写'无'）"和"非目标"，并在 PR 描述里结构化输出。
2. **只有手工 PR、但有评审** → 退到 **B**：PR 模板这三栏设为必填，评审者检查。
3. **单人、无评审** → B 的简化版：模板保留三栏，并在状态行写「**最近更新日期 + 依据 PR 号**」。
   它仍会过期，但**过期是可见的**：日期旧了一眼看得出，PR 号可点开核对。
4. **任何情况下都不要新建独立的状态文件**（`PROGRESS.md` / `STATUS.md` / `sessions/` 目录）。
   它们会与 PR 描述、issue 构成多个真相源；实测头部仓库 **0/10** 这么做。

---

## 3. 据此不做的三件事

- ❌ **不建 `PROGRESS.md` / `STATUS.md` / `sessions/`**：多个真相源，且每个会话一个文件必然积累成噪音。
- ❌ **不让检查器判"状态是否新鲜"**：`mtime` 在 `clone` 之后**全部变成 clone 时间**，
  这条规则在 CI 和新机器上永远通过——测的是"你什么时候 clone 的"，不是"状态新不新鲜"。
  语义正确性更无法判定。
- ❌ **不把待办清单写进 `AGENTS.md`**：挤占每次会话的上下文，而清单是最容易腐的东西。

---

## 4. 接手判据

新会话**只读三样**，能回答**四个问题**：

| 读 | 答 |
|---|---|
| 最近 PR 的标题与描述 | 做到哪 |
| 打开中的 issue / PR | 下一步做什么 |
| `AGENTS.md` | 哪些不能碰、为什么是这样（需要时再看 ADR） |

再加一条纪律：**读完先跑一条命令对账**。
文件说的状态可能是过期的，能执行的东西才是真相——这与全书的判据一致：能验证的才算数。

---

## 5. 边界：五种信息各归其位

| 信息 | 载体 | 变化速度 |
|---|---|---|
| 事实（命令、目录、禁区、坑） | `AGENTS.md` | 慢 |
| 决策（为什么不是另一种） | `docs/adr/` | 极慢 |
| 变更（用户可感知的行为） | `CHANGELOG.md` | 每次发布 |
| **状态（做到哪 / 下一步）** | **PR 描述；有 issue 时以 issue 为准** | 每次会话 |
| **待办（未来要做的事）** | **issue（平台原生，有开/关语义）** | 随时 |

一句话：**慢变写文件，快变交给平台，中间态写进 PR。**

这也是"记录层"要拆成两半的原因——把慢变的 ADR 和快变的状态混在一起，正是文档腐烂的结构性来源。

## 6. 本仓库的现状（诚实记录）

**未采用方式 C**：`tools/publish-pr.ps1` 目前只强制 `-Message`，PR 描述是自动生成的套话，没有"下一步"这一栏。

按 [00-接入决策](00-接入决策.md) 的规矩，这属于"未采用项"，应当记进采用记录并写明触发条件，
例如：**等本章定稿后，把发布参数改成必填并回填一次**。

在那之前，接手本仓库时请按第 4 节的判据做，并接受"下一步"这一栏是空的。
