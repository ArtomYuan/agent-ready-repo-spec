# 02 · Repository layout

**English** · [简体中文](02-目录结构.zh-CN.md)

> This chapter answers: **where do things belong?**
> The basis is the same three sources: GitHub's location rules, Claude Code's loading rules, and the actual layout of
> real repositories (survey below).

---

## 0. One overarching principle

**The root directory is an entrance hall, not the repository.**

The root's job is to let a stranger find the entrance within 30 seconds; every detail belongs deeper.
The test is simple: **for each file at the root, can you say in one sentence who opens it and when?**
If you can't, it is in the wrong place.

| vercel/next.js | `docs/` | **AGENTS.md**, CODEOWNERS, ISSUE_TEMPLATE, DISCUSSION_TEMPLATE, workflows | many |
| modelcontextprotocol/servers | `docs/` | ISSUE_TEMPLATE, pull_request_template, workflows | few |

| python/cpython | `Doc/` | ISSUE_TEMPLATE, workflows, CODEOWNERS | many |

Four things to read out of it:

1. **`.github/` exists in 10/10**, and already carries two jobs: platform files and agent instructions.
2. **Docs directory names are not uniform**: `docs/`, `Doc/`, `documentation/` are all real. **Use `docs/` for new
   repos; don't refactor existing ones just to rename.**
3. **Root file counts vary wildly**: `got` has a handful, `vscode` has dozens. Density depends on the build setup
   (monorepo tooling, lots of config) — **it is not "the cleaner the better"**.
4. **Agent material has two placements**: `cli/cli` and `vscode` use `.github/agents` and `.github/skills`;
   the Claude Code family uses `.claude/`.

## 2. The root directory: three traffic lights

### Must have (entrances)

| File | Why it must be at the root |
|---|---|
| `README.md` | GitHub takes the first of `.github/` > root > `docs/`; the root is the default |
| `LICENSE` | the licence must be visible at a glance |
| `.gitignore` | tools read the root by default |
| `AGENTS.md` | the agent reads the root by default; elsewhere it won't be found |

### May have (platform requirements or engineering necessities)

`.github/`, `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, `CODE_OF_CONDUCT.md`,
`package.json` / `pyproject.toml` / `go.mod`, `Makefile`, `.editorconfig`, `.gitattributes`, `CLAUDE.md`, `.mcp.json`

### Should not be there

| Not at the root | Where instead |
|---|---|
| Architecture docs, tutorials, long guides | `docs/` (the root keeps a link) |
| Meeting notes, scratch notes | `docs/notes/` — or don't commit them |
| Generated files, build caches, logs | `.gitignore` |
| A dozen scripts | `scripts/` (and say what they are in the README) |
| Per-environment config copies | `configs/`, or environment variables |
| A directory holding a single file | merge it, or move it deeper |

## 3. `.github/`: platform files and cross-tool agent files

`.github/` is the only location set GitHub recognises, and in practice it carries two kinds of content:

**① Platform files (GitHub only looks here)**

```
.github/
├── CODEOWNERS                    # may also live at the root or in docs/
├── CONTRIBUTING.md               # the human-facing guide (root/.github/docs all work)
├── SECURITY.md                   # private disclosure entry point
├── ISSUE_TEMPLATE/{bug.yml,feature.yml,config.yml}
├── PULL_REQUEST_TEMPLATE.md
├── dependabot.yml
└── workflows/*.yml               # Actions only reads this path
```

**② Cross-tool agent files (optional, but already the practice at top repositories)**

The actual layout of `cli/cli` and `microsoft/vscode`:

```
.github/
├── agents/            # agent roles/workflow definitions (cli/cli: code-review, dependabot-triager…)
├── skills/            # reusable procedures
├── instructions/      # topic-scoped instruction fragments (vscode)
├── hooks/             # tool hooks (vscode)
├── copilot-instructions.md   # what Copilot reads (vscode)
└── AGENTS.md          # next.js keeps a copy of AGENTS.md here too
```

> **The rule**: content that **only Claude Code** consumes → `.claude/`; content **several tools** consume → `.github/`.

## 4. `docs/`: layer it, don't flatten it

### Recommended skeleton

```
docs/
├── index.md            # the map: entry points for the five categories below
├── getting-started/    # tutorial: from zero to running
├── guides/             # task-oriented: how to do X
├── reference/          # lookup: API, config keys, error codes
├── architecture/       # current state: modules, data flow
├── adr/                # decisions: why not the alternative
└── operations/         # deployment, rollback, on-call
```

### Three rules

- **`index.md` is a map, not prose.** Readers arrive to click through, not to read a paragraph.
- **One topic per file; the file name is the topic.** `docs/adr/0007-cursor-pagination.md` is an order of magnitude
  more useful than `docs/design2-final.md`.
- **Long content does not go into the README.** The README answers "should I use it, how do I run it" and nothing more.

### Don't fight the naming

`Doc/` (cpython) and `documentation/` (got) are real. **Use `docs/` for new repos; don't rename existing ones** —
renaming breaks every external link, and the benefit is far smaller than the cost.

## 5. Agent material: `.claude/` or `.github/`

Same concepts, two paths. The mapping:

| Concept | What Claude Code reads | Common cross-tool/GitHub path | Recommendation |
|---|---|---|---|
| Project instructions | `AGENTS.md` (root/subdirs), `CLAUDE.md`, `.claude/CLAUDE.md` | `AGENTS.md`, `.github/copilot-instructions.md` | **`AGENTS.md` at the root**; add a Copilot pointer if needed |
| Permissions and hooks | `.claude/settings.json`, `hooks` config | `.github/hooks/` (vscode) | Claude-only → `.claude/` |
| Topic-scoped rules | `.claude/rules/*.md` (optional `paths`) | `.github/instructions/*` (vscode) | Claude-only → `.claude/` |
| Reusable procedures | `.claude/skills/<name>/SKILL.md` | `.github/skills/` (cli/cli, vscode) | multi-tool → `.github/skills/` |
| Subagents | `.claude/agents/*.md` | `.github/agents/` (cli/cli, vscode) | same |
| Single-file commands | `.claude/commands/*.md` | `.github/commands/` (vscode) | same |
| MCP servers | `.mcp.json` (project root) | `.github/mcp.json` (cli/cli) | commit it if the team shares it |

One line is enough: **Claude-only goes in `.claude/`; anything another tool might consume goes in `.github/`.**
Never keep a copy in both — that is two sources of truth.

## 6. Large repos and monorepos: two patterns

### The official approach: load per directory

Claude Code's [large codebases guide](https://code.claude.com/docs/en/large-codebases) suggests:

- **Shared conventions at the root, plus one per package/subsystem** (`packages/api/CLAUDE.md`, `packages/web/CLAUDE.md`);
- the root file loads at startup; **subdirectory files load only when work reaches them**;
- packages you never touch can be excluded with `claudeMdExcludes`;
- alternatively use `path-scoped rules` (`.claude/rules/*.md` with `paths:`) instead of many files;
- each directory can have **its own skills**.

### The three shapes observed in the wild

| Shape | Example | Trait | Fits |
|---|---|---|---|
| **Router** | `microsoft/vscode`: the root `AGENTS.md` is **271 bytes**, one sentence pointing at `.github/copilot-instructions.md` | the root file only indexes | large repos, many teams, details already split out |
| **Pointer + boundaries** | `python/cpython`: root `AGENTS.md` is **~1 KB** — points at an external AI policy, five principles, "don't auto-generate issues", and a de-duplication command | the root holds only what must be known immediately | projects with an external governance policy |
| **Everything** | `vercel/next.js` 33 KB, `modelcontextprotocol/servers` 51 KB, `cli/cli` 5.8 KB | the root carries all conventions | single team, centralised conventions, able to keep it fresh |

**How to choose**: write the **minimum** "everything" version first (commands + forbidden areas + pitfalls); once it
passes 200 lines, split into the router shape — move detail into `.claude/rules/` or per-directory `AGENTS.md`, and
leave only pointers and boundaries at the root.

## 7. Anti-patterns

| Anti-pattern | Consequence | Do instead |
|---|---|---|
| Thirty files at the root | newcomers can't find the entrance; the agent can't read it all | push down into `docs/`, `scripts/`, `configs/` |
| Agent instructions inside the README | tools can't read it, humans see noise | split out `AGENTS.md` |
| All docs crammed at the root | the root becomes a second docs tree | entrances only; everything else in `docs/` |
| Build output inside `docs/` | repo bloat, noisy diffs | `.gitignore` |
| Agent rules stored in both `.claude/` and `.github/` | two sources of truth, non-deterministic behaviour | pick one by "who consumes it", point from the other |
| Subdirectory `AGENTS.md` files that contradict each other | the agent drifts after loading them | sub-files hold only the delta; don't restate root rules |
| Renaming `Doc/` to `docs/` for consistency | every external link breaks | new repos use `docs/`; leave existing ones alone |
| Committing `settings.local.json` as a template | local paths leak | commit only `settings.json` |
