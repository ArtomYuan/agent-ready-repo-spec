# 01 · 该有什么文档
**[English](01-该有什么文档.md)** · 简体中文

> 这一章只回答一个问题：**一个 GitHub 仓库，应该有哪些文档。**
> 依据不是我的偏好，而是三件事：**GitHub 官方的识别规则**、**Claude Code 的加载规则**、**十个真实仓库的实际布局**（下表）。

---

## 0. 先看实测：别人的仓库到底放了什么

样本：GitHub 自家仓库（`cli/cli`、`github/docs`、`actions/checkout`）、Anthropic（`anthropics/claude-code`）、
以及几个长期维护的知名仓库（`vercel/next.js`、`rust-lang/rust`、`python/cpython`、`microsoft/vscode`、
`modelcontextprotocol/servers`、`sindresorhus/got`）。

| 仓库 | README | LICENSE | CONTRIBUTING(根) | CoC | SECURITY | CHANGELOG | docs 目录 | `.github/` | AGENTS.md | CLAUDE.md |
|---|---|---|---|---|---|---|---|---|---|---|
| cli/cli | ✅ | ✅ | — | — | — | — | `docs/` | ✅ | ✅ | — |
| github/docs | ✅ | ✅ | ✅ | — | — | ✅ | — | ✅ | — | — |
| actions/checkout | ✅ | ✅ | ✅ | — | — | ✅ | — | ✅ | — | — |
| vercel/next.js | ✅ | ✅ | ✅ | ✅ | — | — | `docs/` | ✅ | ✅ | — |
| rust-lang/rust | ✅ | ✅ | ✅ | ✅ | — | — | — | ✅ | ✅ | — |
| python/cpython | ✅ | ✅ | — | — | — | — | `Doc/` | ✅ | ✅ | — |
| microsoft/vscode | ✅ | ✅ | ✅ | — | ✅ | — | — | ✅ | ✅ | — |
| anthropics/claude-code | ✅ | ✅ | — | — | ✅ | ✅ | — | ✅ | — | ✅ |
| modelcontextprotocol/servers | ✅ | ✅ | ✅ | ✅ | ✅ | — | `docs/` | ✅ | ✅ | — |
| sindresorhus/got | ✅ | ✅ | — | — | — | — | `documentation/` | ✅ | — | — |

读出来的四件事：

1. **README + LICENSE + `.github/` 是 100% 的**（10/10）。
2. **CONTRIBUTING / SECURITY / CoC 经常不在根目录**——它们在 `.github/` 下。根目录有 CONTRIBUTING 的只有 6/10。
3. **`AGENTS.md` 已经常见**（本次抽样的 10 个头部仓库里 6 个有；样本非随机、偏开源大仓，只能说明"存在这个做法"，不能说明"多数仓库如此"），**`CLAUDE.md` 是少数**（1/10，而且那一个是 Anthropic 自己的仓库）。
4. **`docs` 目录命名不统一**：`docs/`、`Doc/`、`documentation/` 都有——所以任何"必须叫 docs"的规定都会误伤真实仓库。

## 1. 三档清单

文档不是"越多越专业"。按**谁要它**分三档，缺哪一档的后果完全不同。

### 第一档：平台要的（缺了直接影响可用性）

| 文件 | GitHub 认它的规则 | 缺了会怎样 |
|---|---|---|
| `README.md` | 取 `.github/` > 根 > `docs/` 的**第一个** | 仓库首页空白，别人无法判断"要不要用" |
| `LICENSE` | 根目录；`LICENSE.md` / `COPYING` 也认 | 默认"保留所有权利"，别人不能合法使用 |
| `.github/CONTRIBUTING.md` | 根 / `.github/` / `docs/`，**文件名不区分大小写**，`.rst` 也认 | 新建 Issue/PR 时没有"贡献前请读"的提示 |
| `.github/SECURITY.md` | 同上三个位置 | 没有私密漏洞上报入口，漏洞会进公开 issue |
| `.github/ISSUE_TEMPLATE/*.yml` | **只能**放 `.github/ISSUE_TEMPLATE/` | 不出现模板选择器；社区档案不打勾 |
| `.github/PULL_REQUEST_TEMPLATE.md` | `.github/` 或根（大小写均可） | 每个 PR 的描述质量靠自觉 |
| `.github/CODEOWNERS` | `.github/` / 根 / `docs/` | 评审靠 @ 人，容易漏 |

两个容易踩的边界：

- **GitHub 只认固定位置的文件，不认"目录"**。`contributing/` 目录本身不算数——必须有入口文件指过去（`github/docs` 就是这么做的：`.github/CONTRIBUTING.md` 指向根下的 `contributing/` 长文）。
- **组织级可以一次配好**：把 `CONTRIBUTING` / `SECURITY` / `CODE_OF_CONDUCT` / `ISSUE_TEMPLATE` 放进一个**公开的、名为 `.github` 的仓库**，全组织生效，单仓库同名文件覆盖。

### 第二档：协作用的（缺了协作会变形）

| 文件 | 职责 | 什么时候可以不要 |
|---|---|---|
| `CHANGELOG.md` | 记录"用户可感知的行为变化"，是版本升级的依据 | 从不发版、或纯内部试验仓库 |
| `CONTRIBUTING.md` | 分支模型、提交格式、PR 流程、评审 SLA | 私有库且不收外部 PR |
| `CODE_OF_CONDUCT.md` | 社区行为标准与举报路径 | 内部库、或贡献者全在一个团队里 |
| `SUPPORT.md` | 把"怎么用/去哪问"从 issue 分流出去 | 有 Discussions 或论坛时通常不需要 |
| `ACCESSIBILITY.md` | 无障碍目标、已知障碍、上报通道（`cli/cli` 就有） | 无 UI 的库 |
| `GOVERNANCE.md` / `MAINTAINERS.md` | 谁有权 merge、怎么成为维护者 | 单人项目 |
| `CITATION.cff` | 被引用时的规范引用 | 非学术项目 |

### 第三档：agent 要的（缺了 agent 会瞎猜）

| 文件 | 谁读它 | 缺了会怎样 |
|---|---|---|
| **`AGENTS.md`（根）** | Claude Code / Codex / Cursor 等，**每次会话全文加载** | agent 不知道命令、目录、禁区，只能从代码里猜 |
| `AGENTS.md`（子目录） | 同上，进入该目录时才加载 | 大仓里根文件被迫写成百科全书 |
| `CLAUDE.md` | 只要 Claude 专属内容时 | 少一个薄层而已，不是必需 |
| `.claude/settings.json` | Claude Code 运行时 | 没有团队共享的权限基线，每个人的门禁不一样 |
| `.claude/skills/*/SKILL.md` | 命中任务时加载 | 多步流程只能塞进 AGENTS.md，占预算 |
| `.claude/agents/*.md` | 派子代理时 | 无法隔离上下文 |
| `.github/copilot-instructions.md` | Copilot / 部分 IDE | 只在用 Copilot 时需要 |

**AGENTS.md 为什么是第一优先**：实测 6/10 的头部仓库已经有它；Claude Code 在没有 `CLAUDE.md` 时**默认直接读它**；
而 `CLAUDE.md` 只有 Anthropic 自己的仓库在用。**跨工具的公共项是 `AGENTS.md`，不是 `CLAUDE.md`。**

## 2. 每份文件的"要不要写"决策

按顺序问三个问题，比背清单快：

```
1. 这个仓库有人会从外部用吗？
   ├─ 是 → README + LICENSE + .github/SECURITY.md + .github/CONTRIBUTING.md
   └─ 否 → README + LICENSE（内部也建议有）+ AGENTS.md

2. 会有人提交 PR 吗？
   ├─ 是 → + CODEOWNERS + PR 模板 + CHANGELOG + 行为准则
   └─ 否 → 跳过这些（但 PR 模板仍然有用：它约束你自己的 PR 描述）

3. 有 agent 参与开发吗？
   └─ 是 → + AGENTS.md（必备）+ .claude/settings.json（要门禁时）+ skills（有副作用流程时）
```

## 3. 新仓库第一天的最小集

不是"最少六件"，而是**按顺序加，每加一件都有明确收益**：

| 天 | 加什么 | 理由 |
|---|---|---|
| 第 1 天 | `README.md`、`LICENSE`、`.gitignore`、`AGENTS.md` | 没有这四样，别人（和人以外的执行者）无法接手 |
| 第 1 周 | `.github/workflows/ci.yml`、PR 模板 | 没有 CI，后面所有门禁都无处挂载 |
| 第 1 个月 | `CHANGELOG.md`、`CODEOWNERS`、`.github/SECURITY.md` | 开始有版本、有评审、有对外面 |
| 之后 | `docs/` + ADR、`CONTRIBUTING.md`、skills | 决策开始累积、流程开始重复时才需要 |

## 4. 三条容易搞错的边界

**① CONTRIBUTING 是写给人看的，不是给 agent 的。**
Claude Code 的加载链里没有它（`memory` 文档中 0 次提及）。要让 agent 遵守贡献规则，办法是在 `AGENTS.md` 里写一句指针——
`cli/cli` 的做法就是：`Read CONTRIBUTING, the canonical contribution policy.`

**② SECURITY / CoC 只在"有外部面"时才是必需。**
实测：`microsoft/vscode`、`anthropics/claude-code`、`modelcontextprotocol/servers` 有 `SECURITY.md`；
`cli/cli`、`next.js`、`rust` 没有根目录的，但它们在 `.github/` 下有（`cli/cli` 还有 `VULNERABILITY_REPORT.yml`）。
真正要看的是"有没有私密上报通道"，而不是"根目录有没有这个文件"。

**③ CHANGELOG 不是 git log。**
实测里只有 3/10 在根目录有 `CHANGELOG.md`——不是因为它不重要，而是很多仓库用 release notes 代替了。
判断标准不是"有没有这个文件"，而是"**用户能不能查到某个版本改了什么**"。
