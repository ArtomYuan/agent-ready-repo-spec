# 规范正文

这一节说明**怎么读这套规范**。逐条规则见 **[checklist.md](checklist.md)** —— 那是规则唯一的事实源。

## 一个仓库的四个成熟阶段

| 级别 | 一句话判据 | 达到它意味着 |
|---|---|---|
| **L0** | 人和 agent 都能在 30 秒内接手 | 有 README / AGENTS.md / .gitignore / LICENSE，CI 能跑 |
| **L1** | 外部贡献者不会问"我该怎么提" | 有 CONTRIBUTING / CODEOWNERS / PR 与 Issue 模板 / CHANGELOG |
| **L2** | 有事能查、有决策能追溯 | 有 SECURITY / 文档地图 / 至少一条 ADR / agent 权限基线 |
| **L3** | agent 的改动可拒绝、可回滚、不腐烂 | AGENTS.md 体积与结构合格、hook 引用有效、文档引用不失效 |

**级别是累积的**：L2 隐含 L0+L1。判断"我到了哪一级"，用**你自己选的目标级别**去比对，
不要拿别人的档位要求自己（见 [guide/00](../guide/00-接入决策.zh-CN.md)）。

## 三档严重度

| 严重度 | 含义 | 典型 |
|---|---|---|
| `must` | 缺了就是硬伤，会在几周内咬人 | 提交了 `settings.local.json`、`.gitignore` 没排除个人配置 |
| `should` | 该有；没有会让协作或治理变形 | 无 CODEOWNERS、无 ADR、`permissions.deny` 为空 |
| `may` | 加分项，视项目规模取舍 | 无 CODE_OF_CONDUCT、无 `.editorconfig`、无 `.gitattributes` |

`may` **不阻断**你达到某个级别。这是刻意的：小项目不该被"加分项"判红。

## 判定靠什么

清单里的每一条都是**结构性判据**：文件在不在、字段有没有、行数超没超、引用还存不存在。

- **没有**"代码质量""测试覆盖率"这类需要主观判断的条目——那种规则会立刻被绕过。
- **没有**"必须用某家 CI / 某个模型 / 哪个 agent 工具"——规范只管可验证的痕迹，不管工具选型。
- 需要判断力的部分，靠**读者**按 [guide/03](../guide/03-文档该怎么写.zh-CN.md) 的判据去读，而不是靠清单。

> 想让机器判？可以，但那是**另一个项目**：本库只提供文本，谁想自动化就自己解析 `checklist.md`
> 或另建数据。理由见 [ADR-0009](../docs/adr/0009-spec-only-no-tooling.md)。

## 提交规则（5 条，分三层）

| 规则 | 级别 | 查什么 | 为什么在这一层 |
|---|---|---|---|
| `R028` | L2 · **may** | 有 `commitlint` 这类**执行载体** | 不是业界基线（`actions/checkout` 只给一条外链），要自动生成 CHANGELOG 时才值得 |
| `R041` | L3 · **may** | 仓库自己的提交约定写进 `AGENTS.md` | agent 默认自带提交/PR 指令，仓库另有约定不写明就会两套打架 |
| `R029` | L2 · should | agent 提交归属未被关闭（`attribution`） | 默认会写 `Co-Authored-By` trailer，关掉就失去审计线索 |
| `R050` | L3 · may | 最近提交的 subject 符合 Conventional Commits | 历史是唯一无法事后伪造的证据 |
| `R051` | L3 · may | 最近提交是线性历史 | 线性历史让 revert / cherry-pick / 审计都简单 |

`R050`/`R051` 需要看 `git log`，属于**抽样自查**，不是每位使用者都必须做的事。
原则：**能查就查，查不到就说"跳过"，绝不说"通过"。**

## 版本策略

- `specVersion` 遵循 SemVer（当前 1.3.0）。
- **新增 `may`/`should` 条目** → minor。
- **把条目改成 `must`，或收紧判据** → major（照做的人会突然"不合格"）。
- 旧条目**只废弃不删除**（在清单里标 `deprecated`），保证历史讨论还能对齐。

## 规范不覆盖什么

以下内容有意排除，因为无法稳定判定，且容易变成走过场：

- 提交信息**内容**写得好不好（只管格式与载体）
- 测试覆盖率阈值
- 代码风格
- "文档写得好不好"（给判据，不给分数）
- 用了哪个 CI / 哪个模型 / 哪个 agent 工具
