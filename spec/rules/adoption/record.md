# 采用记录规则

> 板块 `adoption` · 本页承载 1 条条目：`adoption/record`（L2 · should · 旧 `R063`）
> 讲解与示例见 [guide/00 §2、§5](../../../guide/00-接入决策.zh-CN.md)。

## 一句话

**"我们用了那套规范"必须是一份落在被管理仓库里的文件**，而不是一句口头承诺、
一个 PR 描述、或者某个人的记忆。

## 为什么它是判据，而不只是建议

没有采用记录，会发生两件具体的事：

1. **下一个 agent 会把所有"没有"读成"漏了"**，然后顺手补上不该补的东西。
   agent 看不到你的取舍过程，只看得到当前这棵树。
2. **没人能复审**。规范会改版，去年合理的"不采用"今年可能就不合理了；
   没有一份带日期的记录，就没有"该重新看一遍"这个动作的落点。

写下来的第二个收益更值钱：**"未采用"一旦写出来，它就是一个可被质疑的决定**——
理由站不住脚时别人可以推翻它，而不是猜你的意图。

## 三种载体，任选其一

| 载体 | 适合 | 特点 |
|---|---|---|
| **独立采用记录** `docs/adoption.md` | 想把"用了哪些、没用什么、为什么"一页看完 | 最容易复查；不挤占 ADR 编号（**建议**） |
| **ADR**（`docs/adr/000N-adopt-...md`） | 已有 ADR 习惯，且这次接入本身是架构级决定 | 复用现有流程；但一个 ADR 只该记一个决定，接入往往包含多条 |
| **`AGENTS.md` 里一节** | 小仓库、决策很少 | 人看不到；但 agent 每次都会读到——**这一点很关键** |

## 必含的四样

无论用哪种载体，缺一条就不算有采用记录：

| 项 | 为什么必须有 |
|---|---|
| **采用日期 + `specVersion`** | 规范会改版。没有版本锚，"符合"这两个字没有可对照的对象 |
| **目标档位** | 符合性是按档位判的（L0…目标档位的全部 `must`）。不写档位，声明无法判定 |
| **每项决定与落点** | "做了"必须能被验证——落点是那个文件、那条设置、那个开关 |
| **未采用项及理由** | 见上一节：不写理由，下一个人就会"顺手补上" |

再加一项**复审日期**——它把这份文件从"一次性交代"变成"会过期的记录"。

## 设置也要记

治理类条目（[分支保护](../settings/branch-protection.md)、[CI](../settings/ci.md)）的落点是**平台设置**，
不是文件，所以最容易只存在于某个人的点击历史里。在采用记录里加一节：

```markdown
## 设置（2026-11-18）

| 设置 | 值 | 谁能改 |
|---|---|---|
| 合并方式 | 只允许 squash | @owner |
| 必需检查 | 链接检查、双语配对 | @owner |
| 管理员绕过 | 不允许；破窗见 ADR-0010 | @owner |
| Actions 默认权限 | 只读 | @owner |
```

**少了"谁能改"这一列，这张表记录的是愿望，不是状态。** 仓库被自己的开关锁死时，
你需要立刻知道该去找谁——这正是本库那次事故的直接教训。

## 三个常见误区

| 误区 | 问题 | 正确做法 |
|---|---|---|
| "既然规范里有，就都做了" | 维护成本失控，最后没人守 | 按目标档位与团队规模做减法 |
| "先写在文档里，门禁以后再说" | 半年后还是没门禁，但大家都以为有 | 没有落点就标为"未采用" |
| "照抄别人的采用记录" | 组织信息（谁审批、SLA 几天）不同 | 抄结构，不抄结论 |

## 条目

### 采用记录存在于被管理的那个仓库内

`adoption/record` · L2 · should · 旧 `R063`

**为什么。** 没有它，"我们用了那套规范"只剩口头承诺；下一个 agent 会把所有"没有"读成"漏了"，
然后顺手补上不该补的东西——这正是 [guide/00](../../../guide/00-接入决策.zh-CN.md)
里"为什么未采用也要写"那一条要解决的问题，但它此前只是指导，没有判据。

**怎么做。** 复制 [templates/adoption.md.tmpl](../../../templates/adoption.md.tmpl) 到 `docs/`，
填：`specVersion`、目标档位、每项决策的**落点**、**未采用项与理由**、复审日期。
