# 内容规则

> 板块 `release` · 本页承载 3 条条目：`release/notes-sections`（L2 · should · 旧 `R065`）·
> `release/no-stale-numbers`（L2 · should · 旧 `R066`）· `release/self-noncompliance`（L3 · may · 旧 `R069`）
> 讲解与出处见 [guide/06 §2.3](../../../guide/06-信息该放哪.zh-CN.md)。

Release 正文只有一个用途：**让使用者只读这一页，就能决定"我现在要不要升、升了要改什么"**。
这一篇管三件事：正文必须有哪几节、哪两类文字一律不写、以及规范类项目怎么自曝不合格。
什么时候发、版本号怎么定见 [版本号规则](version.md)；tag 与 CHANGELOG 见 [发布物规则](artifact.md)。

## 模板（控制在 20 行内）

```markdown
## v1.2.0

一句话：这个版本最重要的变化。

### 升级注意
- 破坏性变更与迁移步骤；没有就写"无破坏性变更"。

### 新增 / 变更 / 修复
- 各不超过 5 条；细节指向 CHANGELOG 或 PR，不在这里展开。

### 已知问题
- …

### 校验
- 产物哈希 / 签名（发布二进制时才需要）
```

**20 行是硬约束，不是风格偏好。** 超过它，读者就不读了；读者不读，"升级注意"等于没写。
细节的归属地是 CHANGELOG 和 PR，不是这里。

四节里最容易省、也最不能省的是**「升级注意」**：它是读者唯一决定"要不要停下来读"的开关。
没有破坏性变更也要显式写"无破坏性变更"——空节和缺节是两种不同的信号，前者是结论，后者是遗漏。

## 发布物里腐烂最快的两类文字

这两类本库在 `1.5.0` 发布当天全写进去了，当天就全修掉了（#37 / #38 / #39）：

| 类型 | 长什么样 | 为什么必烂 | 换成什么 |
|---|---|---|---|
| **会变的计数** | "37 条""48 项""12 个接口" | 下一个 PR 就推翻它，而发布物没人回来改 | 指向 `specVersion` 或唯一事实源 |
| **状态句** | "尚未完成""卡在 X""待人工执行" | 要么它已做完（那这句话是错的），要么它没做完（那它属于带 owner 的 issue） | 进 issue，别进发布物 |

判据很简单：**这句话在下一个 PR 之后还成立吗？** 不成立就别写。

## 规范类项目的额外一条

规范库最大的信誉风险是"自己不符合自己的规范"却不说。说了，读者才知道这些判据在
真实约束下的代价——哪些是真做不到的，哪些是懒得做的。

写法固定三样：**哪一条、为什么没做到、恢复路径**。本库 `1.5.0` 的 `R044`（治理面独立 owner）
就是这么处理的：不辩解，给路径。

## 条目

### Release 正文含四节：升级注意 / 新增·变更·修复 / 已知问题 / 校验

`release/notes-sections` · L2 · should · 旧 `R065`

**为什么。** 判据是"使用者只读 Release 就能决定现在升不升、升了要改什么"。
缺任何一节，这个判断就做不出来——尤其是"升级注意"，它决定要不要停下来读。

**怎么做。** 按 [guide/06](../../../guide/06-信息该放哪.zh-CN.md) §2.3 的模板（本页上方）写，20 行内；
细节指向 CHANGELOG 与 PR，不在正文展开。

### Release 与 CHANGELOG 里不写会失效的计数和状态句

`release/no-stale-numbers` · L2 · should · 旧 `R066`

**为什么。** 这是发布物里腐烂最快的一类，而且没人会回来改。本库 `1.5.0` 发布当天写下三处
（条数、"这一步改不了"、描述里的 `48 rules`），当天全部由 #37 / #38 / #39 修掉。

**怎么做。** 计数指向 `specVersion` 或唯一事实源；状态要么已完成，要么进 issue 带 owner——
不进发布物。

### 规范类项目的 Release 在「已知问题」里列出自己不合格的条目

`release/self-noncompliance` · L3 · may · 旧 `R069`

**为什么。** 规范库最大的信誉风险是"自己不符合自己的规范"却不说。说了，读者才知道
这些判据在真实约束下的代价。

**怎么做。** 每条写三样：哪一条、为什么没做到、恢复路径。示例见 `1.5.0` 的 `R044`。
