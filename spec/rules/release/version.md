# 版本号规则

> 板块 `release` · 本页承载 1 条条目：`release/version-bump-why`（L2 · should · 旧 `R070`）
> 讲解与出处见 [guide/06 §2.1–2.2](../../../guide/06-信息该放哪.zh-CN.md)。

发布有三样产物，**版本号是它们的共同坐标**。这一篇管三件事：什么时候该有新版本号、
新版本号的哪一位该动、以及怎么让"动对了"这件事**可被检查**。
正文写什么见 [内容规则](content.md)，tag 与 CHANGELOG 见 [发布物规则](artifact.md)。

## 什么时候该有新版本号

满足其一就发，**不满足就别发**：

1. **累积了使用者可感知的变更**——CHANGELOG 的 `[Unreleased]` 里至少一条 Added / Changed / Fixed，
   且**不是内部重构**；
2. **安全或数据正确性修复**——立即发，不等批次；
3. **平台或依赖变更导致旧版本不可用**——兼容性发布会。

**不要因为**这些原因发：攒了很多提交、到这个月了、想要有个版本号。
第 1 条里的"可感知"是唯一的刹车：判据不是改了多少行，而是**使用者要不要改他这边的东西**。

## 哪一位该动

语义化版本 `MAJOR.MINOR.PATCH`，三位各自对应"读者的处境"：

| 位 | 什么时候动 | 读者的处境 |
|---|---|---|
| **MAJOR** | 破坏性变更：删了东西、改了语义、收紧判据、换了标识符 | 照原样用会坏，**必须**读迁移说明 |
| **MINOR** | 新增能力，向后兼容：新条目、新字段、新板块 | 什么都不用改，但可能想用新的 |
| **PATCH** | 不改变任何判定结果：错别字、补例子、把话说清楚 | 什么都不用做 |

规范类项目还要声明一个 **`specVersion`**：它和被指导仓库自己的包版本无关，
只表示"我采用的是哪一版规范"。采用记录里写的就是这个数，所以它必须**可锚定**——
见 [artifact.md 的 tag 锚点](artifact.md)。

拿不准时按这张表查，**从上往下第一个命中的就是答案**：

| 这批改动里有…… | 升 |
|---|---|
| 把某条从 `should`/`may` 改成 `must` | **major** |
| 收紧已有条目的判据（原来合格的做法现在不合格） | **major** |
| 改规则 ID、改板块划分、改规则文件路径 | **major** |
| 删条目、废弃条目 | **major** |
| 新增 `should` 或 `may` 条目 | minor |
| 新增板块、新增文档章节 | minor |
| 改判据措辞但判定结果不变 | patch |
| 修链接、修错字、补例子 | patch |

**为什么"改 ID / 改路径"算 major**：判据一个字没动，但所有指向旧 ID、旧路径的引用当场失效。
对下游这是破坏性变更，和收紧判据同级。本库 2.0.0 就是按这一条定的。

## 三个常见误判

- **"只是重命名，不算破坏性。"** 只要外部有引用，重命名就是破坏性——引用方不会跟着你的仓库变。
- **"加了 7 条，太多了，得算 major。"** 条数不是判据，**兼容性**才是。7 条新增 `should` 仍是 minor。
- **"改了措辞，怕被说收紧，干脆升 major。"** 升错方向的代价是双向的：无谓的 major 让采用方
  以为要迁移，于是他们不去读**真正的**迁移说明。

## 条目

### 版本号变更要写明升了哪一位、为什么

`release/version-bump-why` · L2 · should · 旧 `R070`

**为什么。** 裸的 `1.5.0 → 1.6.0` 不可验证：读者无法判断这批改动该是 minor（新增 `should`）
还是 major（收紧判据）——**这句话是唯一能让版本号被检查的东西**。少了它，一份写下来的
版本策略就退化成"维护者说了算"，而那正是写策略要防的事。
本库的 SemVer 策略此前只写在 [spec/README.md](../../README.md)「版本策略」里，条目引用数 **0**，
与 `release/tag-and-release` 那一批是同一处漂移。

**怎么做。** 在 CHANGELOG 版本节标题下，或发布提交的信息里，加一句。落点要
**比 PR 描述活得久**——PR 会被 squash 掉，CHANGELOG 不会。

正例：

```
1.5.0 → 1.6.0：新增 7 条发布物判据，全是 should/may，按策略属 minor。
1.6.0 → 2.0.0：规则改成主题文档、ID 换成 板块/主题。判据未变，
               但指向旧路径与 R0xx 的引用失效 → major。
```

反例：

```
## [2.0.0] - 2026-11-20
```

裸的一个标题。没人能判断这次升号对不对，于是版本策略形同不存在。
