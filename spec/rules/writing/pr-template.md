# PR 模板的自检清单规则

> 板块 `writing` · 本页承载 1 条条目：`writing/pr-template-checklist`（L3 · may · 旧 `R039`）
> 讲解见 [guide/03 · 文档该怎么写](../../../guide/03-文档该怎么写.zh-CN.md)。

## 一句话

自检清单的作用不是"让贡献者少漏事"，而是**把"agent 该确认的事"从散文变成可勾选项**——
因为 agent 的 PR 往往"看起来都对"，风险全在**没说出口**的那部分。
一条勾选项要成立，必须同时满足三件事：**对应一条真实存在的硬约定**、**能被"照做一遍"检验**、
**勾错了有后果**。缺任何一件，它就不是清单，是装饰。
"PR 模板该不该存在"不在本页——那是 [协作文档规则](../documents/collaboration.md)。

## 自检清单在解决什么

[guide/03 §6](../../../guide/03-文档该怎么写.zh-CN.md) 给 PR 模板定的目的只有一句：
**让评审者在不追问的情况下拿到判断所需的信息。** 然后紧跟了一句对 agent 的关键判断：

> 对 agent 提交尤其重要：它的 PR 往往"看起来都对"，风险藏在没说的部分。

这就是清单和"改了什么"那一节的分工。「改了什么」描述**做了什么**，清单核对**没漏什么**。
后者对 agent 更值钱，因为 agent 最擅长把"做了什么"写得漂漂亮亮。

清单还有一层作用：**它是评审者注意力的分配器。** 一条勾过的"未触碰禁区"，
等于告诉 reviewer"这一项不用查 diff 了"；一条没勾的"行为变更已更新 CHANGELOG"，
直接把 reviewer 拉去查那个文件。没有清单，reviewer 只能通读 diff——那是最贵的做法。

## 一条勾选项要满足什么

| 要求 | 判法 | 合格的写法 | 不合格的写法 |
|---|---|---|---|
| **对应一条真实存在的约定** | 这句话在 `AGENTS.md` / 规则索引里有没有出处 | `中英两版在同一 PR 内同步` | `代码质量良好` |
| **能被照做一遍检验** | 提交前能不能用一条命令或一次肉眼核对确认 | `文档里的路径都存在` | `文档写得清楚` |
| **勾错了有后果** | 有人（或 CI）会因为这个勾去查 | `CHANGELOG.md 已更新；判据变化已升 specVersion` | `已尽力自查` |
| **是"没漏什么"而不是"做了什么"** | 它是否要求一个 diff 里看不出来的动作 | `新命令 / 新目录已写入 AGENTS.md` | `新增了 3 个文件` |
| **条数在预算内** | 全部勾选项 ≤5 | 见下节 | 12 项 |

第四条最容易被忽略，也最值钱。**diff 里看得出来的事不需要勾**——"新增了 3 个文件"是废话。
清单要盯的是那些**在 diff 里看不见**的动作：改了约定没改索引、加了命令没写进 `AGENTS.md`、
动了 job 名没动 ruleset。本库「已知的坑」里那几条"三处受控双写"，正是这类看不见的动作。

## 上限是 5 条

[guide/03 §6](../../../guide/03-文档该怎么写.zh-CN.md) 写得很直接：**勾选项控制在 5 条以内。勾 12 项的结果是全部乱勾。**

这条不是洁癖，是失效模式：清单超过注意力预算之后，贡献者的行为不是"逐条核对"，
而是"全勾了交上去"——于是清单从**证据**退化成**噪音**，而且比没有更糟，因为它给了 reviewer 一个
"已经自查过"的假信号。

实测两个模板都卡在 5：

| 文件 | 行数 | 复选框总数 | 分布 |
|---|---:|---:|---|
| [templates/PULL_REQUEST_TEMPLATE.md.tmpl](../../../templates/PULL_REQUEST_TEMPLATE.md.tmpl) | 33 | 9 | 影响面 4 + 自检清单 5 |
| [.github/PULL_REQUEST_TEMPLATE.md](../../../.github/PULL_REQUEST_TEMPLATE.md) | 35 | 5 | 全部在自检清单 |

注意"影响面"那 4 个框**不算进自检预算**：它们不是"我确认我做了 X"，而是"这次改动涉及哪些面"，
功能是**路由 reviewer 的注意力**（勾了"公共 API 变更"，reviewer 就去查 CHANGELOG）。
所以 5 条上限管的是**自检**那一节。

## 活样本对照：通用模板 vs 本库模板

同一件事在两种仓库里长得不一样，对照着抄比照抄有用。

| [templates/PULL_REQUEST_TEMPLATE.md.tmpl](../../../templates/PULL_REQUEST_TEMPLATE.md.tmpl)（给被指导仓库） | [.github/PULL_REQUEST_TEMPLATE.md](../../../.github/PULL_REQUEST_TEMPLATE.md)（本库自己用） |
|---|---|
| 已读 `AGENTS.md`，未触碰禁区 | `spec/rules/README.md` 是规则唯一改动源（没有第二份清单） |
| 未修改 `.claude/`、`.github/workflows/`（如需修改已说明理由） | 中英两版在同一 PR 内同步（ADR-0008） |
| 新命令 / 新目录已写入 `AGENTS.md` | `CHANGELOG.md` 已更新；判据变化已升 `specVersion` |
| 行为变更已更新 `CHANGELOG.md` | 没有引入可执行物或规则校验（脚本 / 依赖清单 / 对 `rules/README.md` 的机器校验；`docs.yml` 的文档一致性检查不在此列） |
| 架构 / 选型变更已新增 ADR | 文档里的路径都存在 |

两边共同点是那三条通用的：**禁区 / CHANGELOG / ADR**。差异全部来自各自仓库自己的硬约定——
本库最怕的是"出现第二份规则清单"和"改判据没升版本"，所以那两条进了清单；
通用模板面向普通代码仓库，所以它管"新命令有没有写进 `AGENTS.md`"。

**结论：清单内容不可照抄，只能从你自己仓库的硬约定里长出来。** 抄内容而不抄方法，
得到的是一份"别人仓库的规矩"，贡献者看不懂，reviewer 也不查。

本库模板还有两处结构值得单独抄：

1. **第一节是「本次是否有 agent 参与」**（工具 / 模型 · 人工复核人，没有就写"无"）。
   注释里写明了分工：提交层的线索靠 `Co-Authored-By` trailer，评审层靠这里——两层并存、不互相推翻。
2. **「怎么验证的」里预置三行填空**，每行都要求填**结论**而不是"是"：
   核对过 `spec/rules/README.md` 的相关条目：`<哪几条，结论>`；双语两版是否同步：`<是 / 不适用>`；
   新增/删除的路径是否都有引用方已更新：`<是 / 不适用>`。
   把"不适用"写成合法选项，是为了让"这一项我确实查过、只是与我无关"和"我跳过了"区分得开。

## 勾选项不是闸门：它和门禁的分工

这是本条最容易误判的地方：**勾选项是非确定性机制。** 它靠提交者自觉，模型也一样——
[guide/04 §0](../../../guide/04-Agent怎么用.zh-CN.md) 把指令分成"模型自己决定"和"harness 强制执行"两类，
清单属于前者。所以：

| 你想保证的事 | 清单能做到 | 真正能做到的是 |
|---|---|---|
| 提交者**记得**去查这条约定 | ✅ | —— |
| 提交者**没做也勾了** | ❌ 拦不住 | CI 检查 / hook `exit 2` / deny 规则，见 [权限与 hook 门禁规则](../agent-config/permissions.md) |
| 这件事**绝不能有例外** | ❌ | 分支保护 + 必需检查，见 [分支保护规则](../settings/branch-protection.md) |

同一个道理在 CODEOWNERS 上已经发生过一次：那个文件本身不生效，
**生效的是分支保护里那个 `Require review from Code Owners` 开关**。
清单也一样——它必须有一个"没做就会有人发现"的下游，否则它和 `AGENTS.md` 里的一句散文没有区别。

所以正确的组合是：**清单负责"提醒与留痕"，门禁负责"拦住"**。
一条约定如果重要到"漏了会出事"，它就不该只活在清单里。

## 常见误判

| 误判 | 事实 |
|---|---|
| "有清单就等于有质量把关" | 清单不产生证据，**"怎么验证的"那一栏贴出的真实输出**才产生证据。没有输出的"已测试"等于没测 |
| "清单越长越保险" | 5 条是上限；12 项的结果是全部乱勾，且给 reviewer 假信号 |
| "模板很长就算合格了" | guide/03 §6 的反例原话：**模板很长，但没有任何一栏要求证据** |
| "勾满就是通过" | 勾选项是非确定性线索。要"通过"，得让 CI 或门禁去查它 |
| "有了模板，PR 描述就自动有信息" | 本库实测过反面：[docs/evidence/2026-11-17-repo-self-audit.md](../../../docs/evidence/2026-11-17-repo-self-audit.md) 记录 #3–#6 四个 PR 正文都是 159–165 字符的**同一套模板套话**，信息量≈0，"下一步做什么"完全答不出来。这正是本库后来加「下一步」「非目标」两节的原因 |
| "自检清单能替代 CHANGELOG / ADR" | 清单是**核对动作**，不是记录。行为变化进 CHANGELOG，决策进 ADR，见 [ADR 规则](adr.md) |

## 条目

### PR 模板含自检清单

`writing/pr-template-checklist` · L3 · may · 旧 `R039`

**为什么。** 自检清单把“agent 该确认的事”变成可勾选项，比散文有效。

**怎么做。** 在模板加 - [ ] 项：未触碰禁区、已更新 CHANGELOG、已补 ADR。
