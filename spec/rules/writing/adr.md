# ADR 规则

> 板块 `writing` · 本页承载 2 条条目：`writing/adr-exists`（L2 · should · 旧 `R023`）·
> `writing/adr-naming`（L3 · may · 旧 `R038`）
> 讲解见 [guide/03 · 文档该怎么写](../../../guide/03-文档该怎么写.zh-CN.md)。

## 一句话

ADR 只回答一个问题：**为什么不是另一种做法**。它不是会议纪要，不是 changelog，也不是设计文档的缩写版。
两条条目一个管**有没有**（`adr-exists`，L2——注意它不是 agent 专属要求），一个管**能不能被引用**
（`adr-naming`，L3 · may）。写 ADR 的全部成本换来一句话的回报：半年后有人问"为什么不改成 X"，
仓库答得出，而且答的是**当时的理由**，不是现在的辩解。

## ADR 只回答一个问题：为什么不是另一种做法

[guide/03 §5](../../../guide/03-文档该怎么写.zh-CN.md) 给的理由很具体：
**没有 ADR 的仓库，agent 会每隔几个月把同一批设计重做一遍**——它只看到现状，看不到被否决的选项。

这句话值得拆开看。代码只能证明"现在是这样"，它无法证明"不是那样"。
一个读到 `spec/rules/README.md` 是一张手写的表、而不是 JSON 的 agent，完全有理由提议"生成一份 JSON 更好用"——
这个提议在 1.x 时代**真的存在过**，也真的被推翻了。推翻它的理由不在代码里，在
[ADR-0009](../../../docs/adr/0009-spec-only-no-tooling.md) 里：检查器变相强制运行时、把文档库变成软件项目、
默认了某个工具。没有那份 ADR，这个决定每个新会话都要重打一遍。

同一件事在人类协作里也一样：**能改代码的人，和知道当初为什么这么选的人，通常不是同一个。**

## 什么时候值得写一条

不是每个决定都要 ADR——"函数名怎么起"不需要。值得写的是**会让后来者想推翻的决定**。
本库 13 条 ADR（实测 `docs/adr/` 共 13 个文件，`0001`–`0013`）的触发点可以归成五类，每类都有真实编号：

| 触发 | 长什么样 | 本库实例 |
|---|---|---|
| **真实事故** | 一次代价明确的失败，复盘要能被引用 | [ADR-0010](../../../docs/adr/0010-required-checks-self-lock.md) 必需检查名写错把 `main` 锁死 |
| **覆盖缺口** | 章节写完了、清单 0 条，反复出血三次之后才承认是结构问题 | [ADR-0011](../../../docs/adr/0011-github-management-rules.md) · [ADR-0012](../../../docs/adr/0012-release-notes-spec.md) |
| **推翻自己** | 早期决定在新证据下站不住，要显式取代 | [ADR-0008](../../../docs/adr/0008-bilingual-equal-status.md) 取代 ADR-0007 的第 2 条 · [ADR-0009](../../../docs/adr/0009-spec-only-no-tooling.md) 取代 ADR-0001 / 0002 / 0006 |
| **结构重组** | 影响所有引用方的组织方式 | [ADR-0013](../../../docs/adr/0013-rules-by-domain.md) 规则按板块分目录、ID 换成 `板块/主题` |
| **流程变更** | 改变"变更怎么进仓库"本身 | [ADR-0004](../../../docs/adr/0004-all-changes-via-pr.md) 所有变更走 PR |

反过来，**不该写 ADR 的三种情形**：

- 只是实现细节（换个库、改个内部函数签名）——那是 commit 和 CHANGELOG 的事。
- 还没决定的事——那是 issue。ADR 记的是**已做的决定**，`Proposed` 状态可以有，但别把 ADR 当讨论帖。
- "为了规范化"——`templates/adr.md.tmpl` 在「背景」那栏直接写了这句警告：**不要写"为了规范化"**。

## 四段结构，和每段的可验证版本

骨架：[templates/adr.md.tmpl](../../../templates/adr.md.tmpl)（实测 29 行：状态 / 日期 / 决策者 + 背景 / 选项 / 结论 / 后果 / 相关）。
长度预算 **≤80 行**（[guide/03 §10](../../../guide/03-文档该怎么写.zh-CN.md)）。
每段都有一个"怎么算写对了"的判法：

| 段 | 写什么 | 怎么算写对了 | 本库活样本 |
|---|---|---|---|
| **背景** | 现状是什么、为什么这个决定**现在**必须做 | 读得出触发事件，而不是"为了更好" | ADR-0011 背景直接摊开 1.4.0 的 37 条数了一遍，指出"GitHub 平台管理"这一类**条数为 0** |
| **选项** | 2–4 个真实存在的选项，**每个都写利弊** | 每个被否决的选项都有一句"为什么不选" | ADR-0009 的选项 2 是"换成另一门语言"，一句就否掉：解决某一门语言的问题，仍然是要求使用者运行代码 |
| **结论** | 选哪个、最重要的一条理由 | 一句话能复述 | ADR-0013：放弃"ID 即路径"这个强性质，换"一篇文档讲透一个话题" |
| **后果** | 正面 / **负面** / 迁移 | 负面栏有具体代价，不是"需要持续维护" | ADR-0011 的负面栏写着条目数 37 → 48、L2 号段用满导致"号段 = 档位"这个隐含约定不再成立、`R046` 只有三个仓库的证据、11 条新条目**没有一条经过外部实测** |

三条硬要求，都来自 guide/03 §5：

1. **一个 ADR 只记一个决定。** 塞三个决定的 ADR，半年后没人能引用——因为"引用 ADR-0003"无法说明是哪一段。
2. **选项必须写"为什么不选"。** 只写结论的 ADR 等于没有 ADR：它只能证明"选了 A"，不能阻止下一个人再提 B。
3. **后果要诚实写代价。** 只写优点的 ADR 是宣传，不是记录。

还有一条本库自己加的做法值得抄：**给 ADR 一个复审日期和触发条件**。
[ADR-0011](../../../docs/adr/0011-github-management-rules.md) 末尾写着"2027-01-31，或与 ADR-0008 的复审合并进行"，
并列出触发条件（出现"某条规则根本无法判定"的反例，或有人把它升到 `must`——那是 major）。
没有这一节，ADR 会变成一份"当时说得通"的化石。

## 编号、命名、废弃：为什么永不删除

`writing/adr-naming` 的判据只有一句"文件名符合 `NNNN-` 规则"，但它撑着一整条引用链。

**命名**：`NNNN-短横线标题.md`，四位递增，全小写。本库实测 13 个文件全部符合，
例如 `0013-rules-by-domain.md`、`0003-why-this-repo-delays-admin-enforcement.md`。
四位而不是两位：两位在 `99` 之后要么截断要么改宽度，而改宽度会让所有已有链接当场失效。

**为什么永不删除，只标 Superseded**：决策的历史价值在于"**当时为什么这么想**"。
删掉一条被推翻的 ADR，等于删掉"我们试过这条路"这个事实——下一个人会再试一次。
本库的真实形态比"整篇取代"更细：

- [ADR-0008](../../../docs/adr/0008-bilingual-equal-status.md) 的元数据行写的是取代 ADR-0007 的**第 2 条**
  （"英文是事实源、以英文为准"），ADR-0007 的其他结论仍然有效。
- [ADR-0013](../../../docs/adr/0013-rules-by-domain.md) 写的是**部分修订** ADR-0009 的落点约定，
  并且专门开一节「为什么不违反 ADR-0009」，论证被修订的是落点、**理由不变**。

这两例说明：**取代可以是指名到段的**。"整篇作废"是个粗暴默认，真实世界里的推翻多半只推翻一半。

**状态行允许带落地进度。** ADR-0013 落地期间，状态行不是光秃秃一个 `Accepted`，而是
"Accepted（`release/` `settings/` `adoption/` 已落地，14 条；其余 5 个板块 41 条待重做）"，
做完才改成"8 个板块全部落地：55 条规则收在 22 篇主题文档"。
这比事后补一条"ADR-0014：0013 只做了一半"诚实得多，也省一次编号。

**回退路径也写进 ADR。** ADR-0013 有一节「怎么回退」：回退 = `git revert` 这次重组的提交，
旧文件原样回来，`R0xx` 从未改过所以零损失。**一条没有回退方案的 ADR，读者无法评估它的风险有多大。**

**编号是引用锚点，所以它同时是约束**：`docs/adr/` 里的编号被 `AGENTS.md`、`spec/rules/README.md`、
CHANGELOG、PR 描述反复引用。命名一乱，交叉引用就断——这就是 `adr-naming` 存在的全部理由。
它停在 `may` 也在这里：命名不一致会让引用变麻烦，但不会在几周内咬人。

## 常见误判

| 误判 | 为什么是错的 | 改法 |
|---|---|---|
| 把 ADR 写成会议纪要（谁说了什么） | ADR 记的是**决策**：选了什么、为什么、代价是什么 | 讨论进 issue / PR，结论进 ADR |
| 事后补一条 ADR 编造理由 | guide/03 §5 原话：**比没有更糟**，会误导后来者 | 补记录就写明"这是事后追记"，理由只写当时真实成立的那条 |
| 一条 ADR 塞三个决定 | 半年后没人能引用它——"引用 ADR-0003"说不清是哪一段 | 一个决定一条，宁可编号多 |
| 只写结论，不写"为什么不选 B" | 它只能证明"选了 A"，挡不住下一个人再提 B | 每个被否决的选项一句代价 |
| 用 ADR 复述规则判据 | 判据的归属地是主题文档的「条目」小节，别处只引用不复制（`AGENTS.md` 硬约定） | ADR 里可以出现"哪个 ID 落在哪个文件"这类**历史事实**，判据正文只链过去 |
| 把 ADR 当 CHANGELOG | CHANGELOG 记"行为变了"，ADR 记"为什么这么选"；两者读者不同 | 用户可感知的变化进 CHANGELOG，见 [发布物规则](../release/artifact.md) |
| 以为 ADR 是 agent 专属（L3） | `adr-exists` 在 **L2**：它解决的是"可追溯"，任何有外部使用者的仓库都需要 | 见 [spec/README.md](../../README.md)「四个成熟阶段」 |

## 条目

### 至少有一条 ADR

`writing/adr-exists` · L2 · should · 旧 `R023`

**为什么。** 没有 ADR，agent 会每隔几个月把同一批设计重做一遍——它只看到现状，看不到为什么不是另一种。

**怎么做。** 建 docs/adr/0001-<slug>.md：背景 / 选项 / 结论 / 后果。

### ADR 文件名符合 NNNN- 规则

`writing/adr-naming` · L3 · may · 旧 `R038`

**为什么。** 编号是 ADR 的引用锚点，命名不一致就无法交叉引用。

**怎么做。** 重命名为 0001-lowercase-slug.md，永不删除，只标 Superseded。
