# Agent 操作手册

> 你是替人打理某个仓库的 agent，现在拿到了这套规范。按下面的顺序做，不要跳步。

| 任务 | 读什么 | 产出 |
|---|---|---|
| 给一个存量仓库做体检 | [guide/00](../guide/00-接入决策.zh-CN.md) → [checklist.md](checklist.md) | 一份"已有 / 建议补 / 跳过 + 理由"的清单 |
| 新建仓库 | guide [01](../guide/01-该有什么文档.zh-CN.md) → [02](../guide/02-目录结构.zh-CN.md) → [03](../guide/03-文档该怎么写.zh-CN.md) | 按 [guide/01 第 3 节](../guide/01-该有什么文档.zh-CN.md) 的"第 1 天最小集"落地 |
| 写某一份文档 | [guide/03](../guide/03-文档该怎么写.zh-CN.md) 对应那一节 | 一份照骨架写的文件 |

## 2. 体检怎么做（没有脚本可用，这是设计）

1. 打开 [checklist.md](checklist.md)，**逐条**问三个问题：
   - 有吗？（**看文件系统，不要凭印象**）
   - 没有的话，是"不需要"还是"还没做"？
   - 如果是"不需要"，理由是什么？（写下来，这是给下一个人看的）
2. 输出三段：**已有**（可以引用为范例）/ **建议补**（按影响排序，最多 5 条）/ **跳过 + 理由**。
3. **不要给分数，不要给等级**——等级由仓库主人自己选的目标档位决定，不是你来评。

   如果对方想在自己的文档里写"本仓库符合 `agent-ready-repo-spec 1.5.0`，目标档位 L2"，
   **不要替他写**，把 [README.md](README.md) 的「符合性声明」四个条件交给他，让他自己核对并签字：
   全部 `must` 满足 / 每个偏离的 `should` 有书面理由 / 采用记录落在仓库内 / `may` 不计分。
   你的产出是**事实**，声明是**他的责任**。

## 3. 改动手顺序（避免一次性大改）

1. 先做 `must` 且成本低的（README、`.gitignore`、LICENSE、`AGENTS.md`）。
2. 再做会改变协作方式的（分支保护、CODEOWNERS、PR 模板）——这些要人点头。
3. 最后才是内容类（ADR、文档地图、CHANGELOG 的历史补录）。

**每一步单独一个 PR**：混在一起，reviewer 无法判断哪条改动带来了什么影响。

## 4. 什么时候停手

- 要改的是**平台设置**（分支保护、ruleset、Secrets）：先说明"改什么、为什么、风险"，等确认。
- 要动**治理面**（`AGENTS.md`、CODEOWNERS、CI 配置）：同上。
- 检查不通过、或者你不确定某条规则是否适用：**说清楚卡在哪**，不要自己放宽判据。
- 你的改动会让仓库"看起来更好"但没人要求你做：不做。

## 5. 汇报格式

```
做了什么：<一句话>
改了哪些文件：<列表>
怎么验证的：<真实输出或可复现的步骤，不要写"已完成">
下一步：<一条，或者"无">
风险 / 不确定的地方：<明说>
```

最后一行最重要：**把你不确定的地方写出来，比把确定的地方写漂亮更有价值。**
