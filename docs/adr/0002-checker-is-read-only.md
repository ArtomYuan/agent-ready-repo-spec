# ADR-0002：检查器只读，不做自动修复

- 状态：Superseded by [ADR-0009](0009-spec-only-no-tooling.md)（2026-11-17）：检查器已删除
- 日期：2026-11-16
- 决策者：@example-org/spec-owners

## 背景

体检工具最容易滑向“一键修好”。但本规范的核心资产是**判断**，不是**改文件**：一条 FAIL 往往有多个合理修法
（`SECURITY.md` 的响应时限写几天？`CODEOWNERS` 指哪个团队？协议选 MIT 还是 Apache-2.0？），
自动修会把“需要人做的决定”伪装成“已解决”。

## 选项

1. **`--fix` 自动补文件**。快，但会生成一堆占位内容，且占位内容本身会被判为“未完成”。
2. **只读 + 输出 `fix` 建议**，由人或 agent 按建议执行。
3. **只读 + 交互式向导**。比 2 更友好，但把交互逻辑塞进 CI 场景就废了。

## 结论

选 2。检查器只做三件事：**读、判、说**。

- 只读目标目录，不写、不执行目标仓库里的任何脚本。
- 每条 FAIL 必须给出可执行的一句话 `fix`。
- 需要创造性的决定（协议、团队名、SLA）留给 skill `bootstrap-repo` 与人。

## 后果

**正面**

- 可以对任何第三方仓库安全地跑（只读，无副作用）。
- 检查器可以被 CI 无脑调用，不需要幂等设计。
- 判定与修复解耦：规则演进不会意外改动用户代码。

**负面**

- 用户要自己动手，首次接入的摩擦更高。
- `bootstrap-repo` 承担了“建文件”的复杂度，模板质量变得关键。

**缓解**

- `templates/` 提供可复制的最小版本，占位符统一 `{{UPPER_SNAKE}}` 并配清单。
- `bootstrap-repo` skill 明确要求“先 diff 再合并”，禁止覆盖已有文件。
