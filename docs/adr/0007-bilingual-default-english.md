# ADR-0007：默认英文，中文作为可选镜像（已被 ADR-0008 取代）

- 状态：**Superseded by [ADR-0008](0008-bilingual-equal-status.md)**（2026-11-17）——本 ADR 仅保留第 1、3 条（文件名约定、翻译顺序）
- 日期：2026-11-17
- 决策者：@ArtomYuan
- 相关：[README](../README.md) · [README.zh-CN](../README.zh-CN.md) · [guide/](../guide/)

## 背景

本库的正文目前全是中文。对一个要给别人 `uses:` 的公开规范库来说，这带来两个问题：

1. **默认入口是中文**：第一次来的国际读者打开 README 就走；
2. **语言与文件耦合**：以后想加英文版，会面临"改哪个文件、链接指向哪"的混乱。

同时明确一条约束：**必须保持"一份事实源"**——不能出现中英两份各自演进、互相矛盾（这正是本库 `R033` 反对的"双事实源"）。

## 选项

1. **单文件双语并列**（同一文件里中英段落交替）。读者体验差，且大幅拉长每次加载的上下文——对 agent 尤其糟。
2. **中英各维护一套目录**（`docs/en/`、`docs/zh/`）。结构清晰，但两份内容从第一天起就会漂移，需要额外机制同步。
3. **默认英文 + 中文镜像**：`README.md` 为英文，中文放 `README.zh-CN.md`；正文按章推进，每章完成后增加 `*.zh-CN.md` 兄弟文件。

## 结论

选 3，并规定三条：

1. **文件名约定**：默认文件不带语言后缀（`README.md`、`guide/03-文档该怎么写.md`）；
   中文镜像一律加 `.zh-CN`（`README.zh-CN.md`、`guide/03-文档该怎么写.zh-CN.md`）。
   > 章节文件名里的中文标题保持不变（等英文版落地后再统一改名，避免现在就制造大量链接变更）。
2. ~~**谁是事实源**：英文版是事实源，中文是镜像，冲突以英文为准。~~ **已被 [ADR-0008](0008-bilingual-equal-status.md) 取代**：
   两版平权、同 PR 同步、冲突以证据裁定（不以语言裁定）。本 ADR 只保留第 1、3 条（文件名约定、翻译顺序）。
3. **翻译顺序**：入口优先——`README`（已完成）→ `guide/README` → `00`（接入决策）→ `03`（怎么写）→ `01`、`02` → `04`、`05`、`06`。
   理由：读者进门先看入口，再看"怎么动手"，最后才看治理细节。

**在翻译完成前**，英文 README 里明确写一句"正文目前为中文，翻译进行中"，并指向本 ADR——不假装已经双语。

## 后果

**正面**

- 默认入口对国际读者可用；中文读者有一个明确的镜像入口；
- 文件命名规则简单，链接可预测；
- 事实源唯一（英文），不会出现两份各自演进。

**负面**

- 翻译期间会出现"入口英文、正文中文"的割裂——靠 README 的说明和本 ADR 兜住；
- 每改一章要同步改两份，成本翻倍；**在翻译完成前，中文仍是实际维护的那一份**，这一点必须诚实写在 `AGENTS.md` 里，否则下一个人会改错方向。

**边界**：规则 ID、`check.kind`、文件路径**不翻译**——它们是契约，跨语言必须一致。
