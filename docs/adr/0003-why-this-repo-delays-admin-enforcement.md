# ADR-0003：本仓库暂不开启 admin 强制（已被 ADR-0004 取代）

- 状态：**Superseded by [ADR-0004](0004-all-changes-via-pr.md)**（2026-11-17）
- 日期：2026-11-17
- 决策者：@ArtomYuan
- 相关：[guide/05-Agent参与怎么管理.md](../../guide/05-Agent参与怎么管理.md) · [ADR-0002](0002-checker-is-read-only.md)

## 背景

指导正文 05 章给出的一条硬建议是：分支保护里 **`Do not allow bypassing`** 必须开，
否则管理员可以在"赶时间"时绕过所有门禁，整张保护表就成了建议。

本仓库当前的实际状态是 `enforce_admins = false`（管理员可绕过）。原因很具体：

- 单人维护，没有第二位 reviewer；
- 发布方式是用 `tools/publish-github.ps1` 直接向 `main` 提交（**不走 PR**）；
- 一旦开启 admin 强制，上述发布流程会立刻被自己卡死，且没有替代通道。

矛盾在于：**规范的正文说"必须开"，而本仓库没有开。** 如果不处理，就是"写一套、做一套"——
这正是本库最反对的事。所以按 05 章自己的要求：**例外可以被授权，但必须被记录。**

## 选项

1. **立即开启 `Do not allow bypassing`**，同时把发布流程改成 PR。
   代价：单人仓每次发版要给自己开 PR 再合，摩擦显著；而当前唯一的收益是"防未来的自己偷懒"。
2. **暂不开启，但把理由、触发条件、复审时间写进 ADR。**
   代价：在这段时间里，管理员确实可以绕过门禁；出事故时少一道强制回滚点。
3. **不开启，也不记录。**
   代价：文档与现状不一致，且下一个人（或 agent）会以为门禁是硬的。

## 结论

选 2。并且在 `guide/05` 里明确指向本文件，让"例外"是显式的、可被质疑的。

**触发条件**（满足任一即改为选项 1，另开 ADR 替代本文件）：

- 出现第二位维护者；
- 开始接受外部 PR；
- 引入"agent 自动提交"（非人工触发的发布）；
- 仓库转为多人或对外承诺 SLA。

**复审时间**：2027-01-31，或上述任一条件先发生。

## 后果

**正面**

- 单人发布流程不被阻断；
- 规范里的"必须开"没有被悄悄改成"视团队"——**正文保持强硬，例外被单独记录**；
- 后来者能读到"为什么这里不遵守自己写的规范"。

**负面**

- 在触发条件发生前，管理员绕过门禁是可能的；
- 本仓库对自己的规范不是 100% 合规（这是事实，不是疏忽）。

**缓解措施**（已生效）

- 分支保护已关闭 force push 与分支删除——即使绕过评审，历史也不会被重写；
- CI 三个 job（引擎自测 / 自己体检自己 / Windows 兼容）为必需检查；
- 每次发布都留下一条语义化提交，可单条 `git revert`。
