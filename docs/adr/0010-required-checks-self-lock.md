# ADR-0010：必需检查自锁——一次真实事故的复盘与规则

- 状态：Accepted
- 日期：2026-11-17
- 决策者：@ArtomYuan
- 相关：[ADR-0009](0009-spec-only-no-tooling.md) · [guide/05 附录](../../guide/05-Agent参与怎么管理.md) · [AGENTS.md](../../AGENTS.md) 的「main 的保护配置」

## 背景

ADR-0009 把本库改成纯文档形态，删掉了 `checker/`、`tests/`、`action.yml` 与旧的
`.github/workflows/ci.yml`（里面跑 `引擎自测`、`自己体检自己`、`Windows + PowerShell 5.1 兼容`、
`提交信息（commitlint）` 四个 job）。

但 **ruleset 的 `required_status_checks` 仍然要求这四个 context**。于是 PR 永远停在
`Expected — Waiting for status to be reported`：不通过、不失败、不超时。

这次不是假设中的风险，是**真实卡死了合并**，并且前后踩了两次同一个坑。记录下来，因为它比任何
"预防原则"都更有说服力。

## 时间线（都是实际发生过的）

1. 删除 `ci.yml` 的那个 PR（#22）打开后，四个检查永远 pending，合并按钮灰着。
   第一反应是"是不是 Actions 额度用完了"——查了配额 `core 4994/5000`、两个新 job 5–7 秒跑完，
   **不是额度**，是那四个名字根本没有生产者。
2. 改成在 ruleset 里换成新 workflow 的两个 job 名（`链接检查`、`双语配对`）后，#22 合并成功。
3. 但随后读回 ruleset，发现里边的必需检查**又回到了四个老名字**——临时处理没有落地成持久配置。
4. 再次改成两个新名字，这次成功保存，但其中一项写成了 **`双语配队`**（队，38431），
   而 job 上报的是 **`双语配对`**（对，23545）。
5. 用码点逐字比对才发现差一个汉字：

   ```
   ruleset 要求: 双语配队  21452,35821,37197,38431
   job 上报:     双语配对  21452,35821,37197,23545
   ```

   也就是说：**那一项永远不会被上报**，自锁以"看起来已经修好"的形态又存在了一轮。
6. 用下拉列表重新选中正确项后，PR #23 的两个必需检查实跑通过（4s / 5s），
   状态从"永久 pending"变成"只差一次批准"——那才是设计中的状态。

## 根因

| 层 | 根因 |
|---|---|
| 机制 | `required status checks` 存的是**字符串**；它要求"必须有某个东西上报这个名字"。生产者一消失，名字就永久 pending，GitHub 不超时、不认历史提交 |
| 流程 | 删 workflow / 改 job 名被当成"清理"，没人把它当成"拆掉门锁的钥匙" |
| 人为 | 中文名**手打**进 UI，同音字（对/队）让配置看起来对、实际不匹配 |
| 权限 | 拿 App token 干活的人通常**没有** `administration`，改不了 ruleset——自锁之后自己解不开 |

## 结论（四条规则）

1. **必需检查的 context 一律用下拉列表选，不手打。** 列表里就是 GitHub 实际收到的名字，选中即精确匹配。
2. **必需检查名必须写进 `AGENTS.md`。** 已加「main 的保护配置」一节，写明两个名字与"必须与 `docs.yml` 的 job 名逐字一致"。
3. **改 job 名走三步**：先加新名 job（旧名保留）→ 改 ruleset 指向新名 → 下一个 PR 删旧 job。
   **不要在一个 PR 里同时改名和改规则**，也不要在合并后忘了把临时改动作业成持久配置。
4. **采用记录里必须写清"谁有权改 ruleset"。** 否则自锁发生在 agent 身上时，没人能解开。

## 恢复步骤（下次照做）

1. 读 ruleset，列出 `required_status_checks` 的 context；
2. 取当前 workflow 实际产生的 check 名（`GET /commits/{sha}/check-runs`）；
3. **逐字比对**（中文要比码点，肉眼不可靠）；
4. 删掉没有生产者的 context，用下拉重选有效项；
5. 开一个临时 PR 验证"能跑绿 + 能合并"，再删掉它；
6. 事后补一条 ADR——**不写下来的事故会重演**。

## 代价

- 每加一个 workflow job，就多一处需要人记住的耦合；
- 这条规则无法用工具自动校验（本库已无可执行物，见 ADR-0009），只能靠 `AGENTS.md` + 评审。

**但它是 `must` 级的**：一次自锁就能让仓库彻底停止接受变更，而恢复它需要仓库之外的权限。
