# ADR-0008：双语平权——语言跟随读者，不设唯一标准

- 状态：Accepted
- 日期：2026-11-17
- 决策者：@ArtomYuan
- 取代：[ADR-0007](0007-bilingual-default-english.md) 的**第 2 条**（"英文是事实源、以英文为准"）
- 相关：[README](../README.md) · [README.zh-CN](../README.zh-CN.md) · [guide/](../guide/)

## 背景

ADR-0007 定的是"默认英文 + 中文镜像，冲突以英文为准"。它解决了两件事（文件名约定、翻译顺序），
但也引入了一个不该有的等级：**把语言排了序**。

实际使用中这个排序是错的。用哪种语言取决于**读者是谁、他的母语习惯是什么**——一个中文团队内部维护的仓库，
用中文写就是更省事、更准确；同一个仓库对外时，英文是入口。**没有哪一种语言天然是"更权威"的那一份。**

由此产出的规则应当是：**两版都是正式版本，谁都不是镜像。**

## 选项

1. **保持 ADR-0007 的排序**（英文为事实源）。优点是冲突时永远有答案；缺点是它把语言当成了权威来源，
   而且中文团队每次改动都要以非母语为准，反而更容易出错。
2. **双语平权**：两版都是正式版本，同一 PR 内必须同步；冲突时**以证据为准**，不以语言为准。
3. **只保留中文**。放弃国际读者，与本库"要给别人 `uses:`"的定位冲突。

## 结论

选 2。

规则：

1. **两版都是正式版本。** `README.md` 与 `README.zh-CN.md`、`guide/xx.md` 与 `guide/xx.zh-CN.md` 地位相同，
   都可以作为引用目标，都可以被单独链接。
2. **同一 PR 内同步。** 改内容就在同一 PR 里改两种语言；只改一侧视为未完成。
   （唯一的例外是纯翻译 PR：它只改另一侧，内容不变。）
3. **冲突以证据裁定，不以语言裁定。** 两版说法不一致时，看 `docs/evidence/` 的数据、外部链接、或者**跑一遍命令**。
   **事实不分语言。** 谁写错了就改谁，而不是"以英文为准"。
4. **默认文件名 = 主要读者的语言。** 本仓库入口用英文（GitHub 的第一读者是国际用户），这只是**展示顺序**，
   不是等级。中文团队维护自己的仓库时，反过来即可。
5. **不翻译的东西**：规则 ID、`check.kind`、文件路径、命令。它们是契约。

## 后果

**正面**

- 语言不再是权威来源，中文团队用母语维护不会"低一等"；
- 冲突有明确的裁定方式（证据），不需要靠"看哪份更新"猜。

**负面**

- **双份维护，漂移风险是真实的**——这是本决策接受的代价；
- 两边都要读才能确认"改全了"，成本翻倍；
- 没有自动检查能判定"两版内容一致"（语义一致无法机械验证）。

**缓解**

- 把**会变的数字与实测**放进 `docs/evidence/`（语言中性、按日期存档），章节只留结论与指针——
  这样最容易漂移的部分天然只有一份；
- 章节保持短；长的部分拆到证据文件；
- PR 模板的自检项里已有"文档已同步"这一条，靠评审兜住。

## 复审

2027-01-31，或出现第三种语言时（届时需要决定是"平权 N 版"还是"主语言 + 镜像"）。
